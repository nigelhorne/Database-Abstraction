   73: =head1 DESCRIPTION
   74: 
   75: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
   76: interface over CSV, PSV, XML, SQLite, DBM::Deep, BerkeleyDB, and Excel (XLSX)
   77: files - local, remote (via SSH), or fetched from a URL - without writing any
   78: SQL.
   79: Effectively it allows you to access a database table, of many different
   80: database formats, as an object.
   81: 
   82: Key features:
   83: 
   84: =over 4
   85: 
   86: =item *
   87: 
   88: B<No SQL required.>  Use plain Perl method calls for simple lookups and
   89: scans; switch storage formats without changing application code.
   90: 
   91: =item *
   92: 
   93: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
   94: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
   95: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
   96: C<-between>), and logical groupings (C<-or>, C<-and>).
   97: 
   98: =item *
   99: 
  100: B<Automatic joins.>  Add a C<join> parameter to any select method to
  101: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
  102: 
  103: =item *
  104: 
  105: B<Chained query builder.>  The C<query()> method returns a
  106: L<Database::Abstraction::Query> object for fluent, composable queries:
  107: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  108: 
  109: =item *
  110: 
  111: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  112: returns full type/nullability metadata, using native driver introspection
  113: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  114: 
  115: =item *
  116: 
  117: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  118: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  119: instead of pointing at a local file.
  120: 
  121: =item *
  122: 
  123: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  124: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  125: A CHI-compatible cache layer is also supported.
  126: 
  127: =back

  234: 
  235: The module probes the C<directory> for files in this priority order:
  236: 
  237: =over 4
  238: 
  239: =item 1. C<SQLite>

  243: =item 2. C<Deep>

  247: Requires L<DBM::Deep> (loaded lazily).

  250:

  259: =item 5. C<Excel>
  260: 
  261: Excel workbook ending C<.xlsx>.  Each worksheet is a separate SQL table;
  262: the active worksheet is determined by the class-derived table name (or the

  264: L<DBD::Excel> (loaded lazily); L<Spreadsheet::ParseXLSX> is used
  265: automatically for modern C<.xlsx> files when installed.  No slurp path:

  267: 
  268: =item 6. C<XML>
  269: 
  270: File ending C<.xml>
  271: 
  272: =item 7. C<BerkeleyDB>
  273: 
  274: Binary key-value file ending C<.db>
  275: 
  276: =item 8. C<HTML>
  277: 
  278: Remote HTML page fetched via a URL.  Pass C<url> instead of C<directory>; the

  281: C<html_table_index>-selected) table into memory.  The first row of the table
  282: is treated as column headers.  Both modules are loaded lazily and are not
  283: required for other backends.

  285: =back
  286: 
  287: Pass C<dsn> to bypass file detection entirely and connect via any DBI driver.
  288: Pass C<url> to fetch and slurp a remote HTML table without a local directory.

  290: =head1 QUERY CRITERIA
  291: 
  292: All select methods (C<selectall_arrayref>, C<selectall_array>,
  293: C<fetchrow_hashref>, C<count>) accept the same criteria syntax.
  294: 
  295: =head2 Plain value
  296: 
  297:     status => 'active'          # status = 'active'
  298:     name   => undef             # name IS NULL
  299: 
  300: Values containing C<%> or C<_> are matched with C<LIKE>:
  301: 
  302:     name => 'A%'                # name LIKE 'A%'
  303: 
  304: =head2 Comparison operator hashref
  305: 
  306:     score => { '>'  => 90  }   # score > 90
  307:     score => { '<'  => 50  }   # score < 50
  308:     score => { '>=' => 80  }   # score >= 80
  309:     score => { '<=' => 100 }   # score <= 100
  310:     score => { '!=' => 0   }   # score != 0
  311: 
  312: Multiple operators on one column are ANDed:
  313: 
  314:     score => { '>' => 60, '<' => 90 }   # 60 < score < 90
  315: 
  316: =head2 Pattern matching
  317: 
  318:     name => { -like     => 'A%'  }   # name LIKE 'A%'
  319:     name => { -not_like => 'Z%'  }   # name NOT LIKE 'Z%'
  320: 
  321: =head2 Set membership
  322: 
  323:     name => { -in     => ['Alice', 'Bob'] }   # name IN (...)
  324:     name => { -not_in => ['Alice', 'Bob'] }   # name NOT IN (...)
  325: 
  326: =head2 Range
  327: 
  328:     score => { -between => [60, 90] }   # score BETWEEN 60 AND 90
  329: 
  330: =head2 Logical groupings
  331: 
  332: C<-or> and C<-and> take an arrayref of condition hashrefs:
  333: 
  334:     -or => [
  335:         { status => 'active'        },

  338: 
  339:     -and => [
  340:         { status => 'active'        },

  421: =head2 new
  422: 
  423: Create an object pointing to a read-only database.
  424: 
  425: Accepts arguments as a hash, a hashref, or - as a shortcut - a single bare
  426: string which is taken to be C<directory>.
  427: 
  428: =head3 Connection parameters
  429: 
  430: =over 4
  431: 
  432: =item * C<directory>
  433: 
  434: Directory containing the data files.  The module probes this directory for
  435: files named after the subclass (see L</FILE FORMATS>).  Required unless
  436: C<dsn> is given.
  437: 
  438: =item * C<dsn>
  439: 
  440: A DBI data-source string (e.g. C<dbi:SQLite:dbname=/path/to/db> or
  441: C<dbi:Pg:dbname=mydb;host=db.example.com>).  When present, file detection
  442: is skipped entirely and the DSN is used directly.  The SQL dialect is
  443: inferred from the DSN prefix (C<sqlite>, C<postgres>, C<mysql>).
  444: 
  445: =item * C<username>
  446: 
  447: Database username.  Used only with C<dsn>; ignored for file-based backends.
  448: 
  449: =item * C<password>
  450: 
  451: Database password.  Used only with C<dsn>; ignored for file-based backends.
  452: 
  453: =item * C<dbname>
  454: 
  455: Override the filename stem searched in C<directory> (default: the table
  456: name derived from the class name).
  457: 
  458: =item * C<table>
  459: 
  460: Override the table (or worksheet) name used in SQL queries for this object.
  461: Default is the class-name-derived table name (e.g. C<Database::Foo> =>
  462: C<foo>).  Particularly useful for Excel workbooks where a single F<.xlsx>
  463: file contains multiple worksheets: pass C<< table => 'Summary' >> to query
  464: the C<Summary> worksheet without creating a dedicated subclass.  Also works
  465: with SQLite/DSN connections to select a table other than the class-derived
  466: default.  The filename stem (C<dbname>) continues to fall back to the class
  467: name, so the correct file is opened regardless of this override.  The value
  468: is validated against C<$SAFE_QUALIFIED> at construction time.
  469: 
  470: =item * C<filename>
  471: 
  472: Override the full filename (relative to C<directory>).  Takes precedence
  473: over C<dbname>.
  474: 
  475: =item * C<host>
  476: 
  477: Remote hostname (or C<user@host>) from which to fetch the data file(s) via
  478: SSH/SCP.  When present, each candidate filename is fetched with
  479: L<File::Slurp::Remote> into a local temporary directory; the existing
  480: extension-based file-type detection then runs against that directory.
  481: C<directory> is treated as the remote path (no local canonicalization is
  482: applied).  Using C<filename> together with C<host> avoids probing multiple
  483: extensions and is therefore more efficient.  L<File::Slurp::Remote> must be
  484: installed; it is loaded lazily (only when C<host> is given).
  485: 
  486: =item * C<url>
  487: 
  488: A URL (C<http://> or C<https://>) pointing to an HTML page that contains one
  489: or more C<< <table> >> elements.  When present, C<directory> is not required.
  490: The first row of the selected table is used as column headers.
  491: Requires L<LWP::UserAgent> and L<HTML::TableExtract> (both loaded lazily).
  492: 
  493: =back
