   82: =head1 DESCRIPTION
   83: 
   84: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
   85: interface over CSV, PSV, TSV, JSON, XML, SQLite, DBM::Deep, BerkeleyDB, and
   86: Excel (XLS/XLSX) files - local, remote (via SSH), or fetched from a URL -
   87: without writing any SQL.
   88: Effectively it allows you to access a database table, of many different
   89: database formats, as an object.
   90: 
   91: Key features:
   92: 
   93: =over 4
   94: 
   95: =item *
   96: 
   97: B<No SQL required.>  Use plain Perl method calls for simple lookups and
   98: scans; switch storage formats without changing application code.
   99: 
  100: =item *
  101: 
  102: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
  103: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
  104: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
  105: C<-between>), and logical groupings (C<-or>, C<-and>).
  106: 
  107: =item *
  108: 
  109: B<Automatic joins.>  Add a C<join> parameter to any select method to
  110: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
  111: 
  112: =item *
  113: 
  114: B<Chained query builder.>  The C<query()> method returns a
  115: L<Database::Abstraction::Query> object for fluent, composable queries:
  116: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  117: 
  118: =item *
  119: 
  120: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  121: returns full type/nullability metadata, using native driver introspection
  122: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  123: 
  124: =item *
  125: 
  126: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  127: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  128: instead of pointing at a local file.
  129: 
  130: =item *
  131: 
  132: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  133: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  134: A CHI-compatible cache layer is also supported.
  135: 
  136: =back

  242: =head1 FILE FORMATS
  243: 
  244: The module probes the C<directory> for files in this priority order:
  245: 
  246: =over 4
  247: 
  248: =item 1. C<SQLite>
  249: 
  250: File ending C<.sql>, C<.sqlite>, or C<.sqlite3>.
  251: Requires L<DBD::SQLite>.
  252: 
  253: =item 2. C<Deep>
  254: 
  255: DBM::Deep file ending C<.dbm> or C<.deep>.  The entire file is slurped
  256: into a plain Perl hash on open; all in-memory fast-paths apply.
  257: Requires L<DBM::Deep> (loaded lazily).
  258: 
  259: =item 3. C<PSV>
  260: 
  261: Pipe-separated file, ending C<.psv>.
  262: 
  263: =item 4. C<TSV>
  264: 
  265: Tab-separated file, ending C<.tsv>.
  266: 
  267: =item 5. C<CSV>
  268: 
  269: Comma (or custom) separated file, ending C<.csv> or C<.db>; can be
  270: gzipped (C<.csv.gz> or C<.db.gz>).
  271: B<Note:> the default separator is C<!> not C<,> for historical
  272: reasons - pass C<< sep_char => ',' >> for standard CSVs.
  273: Requires L<Text::xSV::Slurp> for the slurp fast-path (loaded lazily).
  274: 
  275: =item 6. C<Excel> (C<.xls>) and C<XLSX> (C<.xlsx>)
  276: 
  277: Two separate Excel backends - one per file format:
  278: 
  279: =over 4
  280: 
  281: =item B<.xls> - old binary format, opened via L<DBD::Excel> (which uses
  282: L<Spreadsheet::ParseExcel> internally).  All queries go through DBI/SQL;
  283: no in-memory slurp path.  C<max_slurp_size> has no effect.
  284: 
  285: =item B<.xlsx> - modern OOXML format, parsed directly via
  286: L<Spreadsheet::ParseXLSX> and slurped into an in-memory hash (keyed mode)
  287: or array (C<no_entry> mode).  No DBI handle is created; all queries use
  288: the in-memory fast-path.  Complex criteria (operator hashes, C<-or>/C<-and>)
  289: will fall through to the SQL path and croak - use simple scalar criteria.
  290: 
  291: =back
  292: 
  293: For both formats, each worksheet is a separate logical table; the active
  294: worksheet is determined by the class-derived table name (or the C<table>
  295: constructor parameter).  Both modules are loaded lazily.
  296: 
  297: =item 7. C<XML>
  298: 
  299: File ending C<.xml>.
  300: Requires L<XML::Simple> for the slurp fast-path (loaded lazily).
  301: 
  302: =item 8. C<JSON>
  303: 
  304: File ending C<.json>, slurped into memory via L<JSON::MaybeXS> (loaded
  305: lazily).
  306: 
  307: The file may contain either a JSON array of row objects:
  308: 
  309:     [
  310:       { "entry": "key1", "col": "val1" },
  311:       { "entry": "key2", "col": "val2" }
  312:     ]
  313: 
  314: or a JSON object whose keys are the primary-key values:
  315: 
  316:     {
  317:       "key1": { "col": "val1" },
  318:       "key2": { "col": "val2" }
  319:     }
  320: 
  321: In the object form, each key is injected into its row hash under the C<id>
  322: column name (default C<entry>), so all normal lookups work identically to
  323: the array form.
  324: 
  325: A zero-byte or whitespace-only file is treated as empty - all query methods
  326: return 0 / C<undef> / C<[]> without throwing.
  327: Requires L<JSON::MaybeXS> (loaded lazily).
  328: 
  329: =item 9. C<BerkeleyDB>
  330: 
  331: Binary key-value file ending C<.db>.
  332: 
  333: =item 10. C<HTML>
  334: 
  335: HTML page fetched via a C<url>.  Pass C<url => 'https://...'> instead of
  336: C<directory>; the module fetches the page with L<LWP::UserAgent::Cached>, parses all
  337: C<< <table> >> elements with L<HTML::TableExtract>, and slurps the first (or
  338: C<html_table_index>-selected) table into memory.  The first row of the table
  339: is treated as column headers.  Both modules are loaded lazily and are not
  340: required for other backends.
  341: 
  342: =back
  343: 
  344: Pass C<dsn> to bypass file detection entirely and connect via any DBI driver.
  345: Pass C<url> to fetch and slurp data from a remote source without a local
  346: directory.  When the URL returns C<Content-Type: application/json> or the URL
  347: path ends in C<.json>, the response is parsed as JSON (see item 8 above).
  348: Otherwise the response is parsed as an HTML page (item 10).

  492: =head2 new
  493: 
  494: Create an object pointing to a read-only database.
  495: 
  496: Accepts arguments as a hash, a hashref, or - as a shortcut - a single bare
  497: string which is taken to be C<directory>.
  498: 
  499: =head3 Connection parameters
  500: 
  501: =over 4
  502: 
  503: =item * C<directory>
  504: 
  505: Directory containing the data files.  The module probes this directory for
  506: files named after the subclass (see L</FILE FORMATS>).  Required unless
  507: C<dsn> is given.
  508: 
  509: =item * C<dsn>
  510: 
  511: A DBI data-source string (e.g. C<dbi:SQLite:dbname=/path/to/db> or
  512: C<dbi:Pg:dbname=mydb;host=db.example.com>).  When present, file detection
  513: is skipped entirely and the DSN is used directly.  The SQL dialect is
  514: inferred from the DSN prefix (C<sqlite>, C<postgres>, C<mysql>).
  515: 
  516: =item * C<username>
  517: 
  518: Database username.  Used only with C<dsn>; ignored for file-based backends.
  519: 
  520: =item * C<password>
  521: 
  522: Database password.  Used only with C<dsn>; ignored for file-based backends.
  523: 
  524: =item * C<dbname>
  525: 
  526: Override the filename stem searched in C<directory> (default: the table
  527: name derived from the class name).
  528: 
  529: =item * C<table>
  530: 
  531: Override the table (or worksheet) name used in SQL queries for this object.
  532: Default is the class-name-derived table name (e.g. C<Database::Foo> =>
