  108: =head1 DESCRIPTION
  109: 
  110: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
  111: interface over CSV, PSV, TSV, JSON, XML, SQLite, DBM::Deep, BerkeleyDB, and
  112: Excel (XLS/XLSX) files - local, remote (via SSH), or fetched from a URL -
  113: without writing any SQL.
  114: Effectively it allows you to access a database table, of many different
  115: database formats, as an object.
  116: 
  117: Key features:
  118: 
  119: =over 4
  120: 
  121: =item *
  122: 
  123: B<No SQL required.>  Use plain Perl method calls for simple lookups and
  124: scans; switch storage formats without changing application code.
  125: 
  126: =item *
  127: 
  128: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
  129: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
  130: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
  131: C<-between>), and logical groupings (C<-or>, C<-and>).
  132: 
  133: =item *
  134: 
  135: B<Automatic joins.>  Add a C<join> parameter to any select method to
  136: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
  137: 
  138: =item *
  139: 
  140: B<Chained query builder.>  The C<query()> method returns a
  141: L<Database::Abstraction::Query> object for fluent, composable queries:
  142: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  143: 
  144: =item *
  145: 
  146: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  147: returns full type/nullability metadata, using native driver introspection
  148: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  149: 
  150: =item *
  151: 
  152: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  153: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  154: instead of pointing at a local file.
  155: 
  156: =item *
  157: 
  158: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  159: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  160: A CHI-compatible cache layer is also supported.
  161: 
  162: =back
  163:

  268: =head1 FILE FORMATS
  269: 
  270: The module probes the C<directory> for files in this priority order:
  271: 
  272: =over 4
  273: 
  274: =item 1. C<SQLite>
  275: 
  276: File ending C<.sql>, C<.sqlite>, or C<.sqlite3>.
  277: Requires L<DBD::SQLite>.
  278: 
  279: =item 2. C<Deep>
  280: 
  281: DBM::Deep file ending C<.dbm> or C<.deep>.  The entire file is slurped
  282: into a plain Perl hash on open; all in-memory fast-paths apply.
  283: Requires L<DBM::Deep> (loaded lazily).
  284: 
  285: =item 3. C<PSV>
  286: 
  287: Pipe-separated file, ending C<.psv>.
  288: 
  289: =item 4. C<TSV>
  290: 
  291: Tab-separated file, ending C<.tsv>.
  292: 
  293: =item 5. C<CSV>
  294: 
  295: Comma (or custom) separated file, ending C<.csv> or C<.db>; can be
  296: gzipped (C<.csv.gz> or C<.db.gz>).
  297: B<Note:> the default separator is C<!> not C<,> for historical
  298: reasons - pass C<< sep_char => ',' >> for standard CSVs.
  299: Requires L<Text::xSV::Slurp> for the slurp fast-path (loaded lazily).
  300: 
  301: =item 6. C<Excel> (C<.xls>) and C<XLSX> (C<.xlsx>)
  302: 
  303: Two separate Excel backends - one per file format:
  304: 
  305: =over 4
  306: 
  307: =item B<.xls> - old binary format, opened via L<DBD::Excel> (which uses
  308: L<Spreadsheet::ParseExcel> internally).  All queries go through DBI/SQL;
  309: no in-memory slurp path.  C<max_slurp_size> has no effect.
  310: 
  311: =item B<.xlsx> - modern OOXML format, parsed directly via
  312: L<Spreadsheet::ParseXLSX> and slurped into an in-memory hash (keyed mode)
  313: or array (C<no_entry> mode).  No DBI handle is created; all queries use
  314: the in-memory fast-path.  Complex criteria (operator hashes, C<-or>/C<-and>)
  315: will fall through to the SQL path and croak - use simple scalar criteria.
  316: 
  317: =back
  318: 
  319: For both formats, each worksheet is a separate logical table; the active
  320: worksheet is determined by the class-derived table name (or the C<table>
  321: constructor parameter).  Both modules are loaded lazily.
  322: 
  323: =item 7. C<XML>
  324: 
  325: File ending C<.xml>.
  326: Requires L<XML::Simple> for the slurp fast-path (loaded lazily).
  327: 
  328: =item 8. C<JSON>
  329: 
  330: File ending C<.json>, slurped into memory via L<JSON::MaybeXS> (loaded
  331: lazily).
  332: 
  333: The file may contain either a JSON array of row objects:
  334: 
  335:     [
  336:       { "entry": "key1", "col": "val1" },
  337:       { "entry": "key2", "col": "val2" }
  338:     ]
  339: 
  340: or a JSON object whose keys are the primary-key values:
  341: 
  342:     {
  343:       "key1": { "col": "val1" },
  344:       "key2": { "col": "val2" }
  345:     }
  346: 
  347: In the object form, each key is injected into its row hash under the C<id>
  348: column name (default C<entry>), so all normal lookups work identically to
  349: the array form.
  350: 
  351: A zero-byte or whitespace-only file is treated as empty - all query methods
  352: return 0 / C<undef> / C<[]> without throwing.
  353: Requires L<JSON::MaybeXS> (loaded lazily).
  354: 
  355: =item 9. C<BerkeleyDB>
  356: 
  357: Binary key-value file ending C<.db>.
  358: 
  359: =item 10. C<HTML>
  360: 
  361: HTML page fetched via a C<url>.  Pass C<url => 'https://...'> instead of
  362: C<directory>; the module fetches the page with L<LWP::UserAgent::Cached>, parses all
  363: C<< <table> >> elements with L<HTML::TableExtract>, and slurps the first (or
  364: C<html_table_index>-selected) table into memory.  The first row of the table
  365: is treated as column headers.  Both modules are loaded lazily and are not
  366: required for other backends.
  367: 
  368: =back
  369: 
  370: Pass C<dsn> to bypass file detection entirely and connect via any DBI driver.
  371: Pass C<url> to fetch and slurp data from a remote source without a local
  372: directory.  When the URL returns C<Content-Type: application/json> or the URL
  373: path ends in C<.json>, the response is parsed as JSON (see item 8 above).
  374: Otherwise the response is parsed as an HTML page (item 10).

  518: =head2 new
  519: 
  520: Create an object pointing to a read-only database.
  521: 
  522: Accepts arguments as a hash, a hashref, or - as a shortcut - a single bare

  525: =head3 Connection parameters
  526: 
  527: =over 4
  528: 
  529: =item * C<directory>
  530: 
  531: Directory containing the data files.  The module probes this directory for
  532: files named after the subclass (see L</FILE FORMATS>).  Required unless
  533: C<dsn> is given.
  534:

  536:

  539: is skipped entirely and the DSN is used directly.  The SQL dialect is
  540: inferred from the DSN prefix (C<sqlite>, C<postgres>, C<mysql>).

  542: =item * C<username>
  543: 
  544: Database username.  Used only with C<dsn>; ignored for file-based backends.

  546: =item * C<password>
