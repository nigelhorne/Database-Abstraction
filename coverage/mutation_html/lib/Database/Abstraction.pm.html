   73: =head1 DESCRIPTION
   74: 
   75: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
   76: interface over CSV, PSV, TSV, JSON, XML, SQLite, DBM::Deep, BerkeleyDB, and
   77: Excel (XLS/XLSX) files - local, remote (via SSH), or fetched from a URL -
   78: without writing any SQL.
   79: Effectively it allows you to access a database table, of many different
   80: database formats, as an object.
   81: 
   82: Key features:
   83: 
   84: =over 4
   85: 
   86: =item *
   87: 
   88: B<No SQL required.>  Use plain Perl method calls for simple lookups and
   89: scans; switch storage formats without changing application code.
   90: 
   91: =item *
   92: 
   93: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
   94: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
   95: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
   96: C<-between>), and logical groupings (C<-or>, C<-and>).
   97: 
   98: =item *
   99: 
  100: B<Automatic joins.>  Add a C<join> parameter to any select method to
  101: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
  102: 
  103: =item *
  104: 
  105: B<Chained query builder.>  The C<query()> method returns a
  106: L<Database::Abstraction::Query> object for fluent, composable queries:
  107: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  108: 
  109: =item *
  110: 
  111: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  112: returns full type/nullability metadata, using native driver introspection
  113: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  114: 
  115: =item *
  116: 
  117: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  118: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  119: instead of pointing at a local file.
  120: 
  121: =item *
  122: 
  123: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  124: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  125: A CHI-compatible cache layer is also supported.
  126: 
  127: =back

  233: =head1 FILE FORMATS
  234: 
  235: The module probes the C<directory> for files in this priority order:
  236: 
  237: =over 4
  238: 
  239: =item 1. C<SQLite>
  240: 
  241: File ending C<.sql>, C<.sqlite>, or C<.sqlite3>.
  242: Requires L<DBD::SQLite>.
  243: 
  244: =item 2. C<Deep>
  245: 
  246: DBM::Deep file ending C<.dbm> or C<.deep>.  The entire file is slurped
  247: into a plain Perl hash on open; all in-memory fast-paths apply.
  248: Requires L<DBM::Deep> (loaded lazily).
  249: 
  250: =item 3. C<PSV>
  251: 
  252: Pipe-separated file, ending C<.psv>.
  253: 
  254: =item 4. C<TSV>
  255: 
  256: Tab-separated file, ending C<.tsv>.
  257: 
  258: =item 5. C<CSV>
  259: 
  260: Comma (or custom) separated file, ending C<.csv> or C<.db>; can be
  261: gzipped (C<.csv.gz> or C<.db.gz>).
  262: B<Note:> the default separator is C<!> not C<,> for historical
  263: reasons - pass C<< sep_char => ',' >> for standard CSVs.
  264: Requires L<Text::xSV::Slurp> for the slurp fast-path (loaded lazily).
  265: 
  266: =item 6. C<Excel> (C<.xls>) and C<XLSX> (C<.xlsx>)
  267: 
  268: Two separate Excel backends - one per file format:
  269: 
  270: =over 4
  271: 
  272: =item B<.xls> - old binary format, opened via L<DBD::Excel> (which uses
  273: L<Spreadsheet::ParseExcel> internally).  All queries go through DBI/SQL;
  274: no in-memory slurp path.  C<max_slurp_size> has no effect.
  275: 
  276: =item B<.xlsx> - modern OOXML format, parsed directly via
  277: L<Spreadsheet::ParseXLSX> and slurped into an in-memory hash (keyed mode)
  278: or array (C<no_entry> mode).  No DBI handle is created; all queries use
  279: the in-memory fast-path.  Complex criteria (operator hashes, C<-or>/C<-and>)
  280: will fall through to the SQL path and croak - use simple scalar criteria.
  281: 
  282: =back
  283: 
  284: For both formats, each worksheet is a separate logical table; the active
  285: worksheet is determined by the class-derived table name (or the C<table>
  286: constructor parameter).  Both modules are loaded lazily.
  287: 
  288: =item 7. C<XML>
  289: 
  290: File ending C<.xml>.
  291: Requires L<XML::Simple> for the slurp fast-path (loaded lazily).
  292: 
  293: =item 8. C<JSON>
  294: 
  295: File ending C<.json>, slurped into memory via L<JSON::MaybeXS> (loaded
  296: lazily).
  297: 
  298: The file may contain either a JSON array of row objects:
  299: 
  300:     [
  301:       { "entry": "key1", "col": "val1" },
  302:       { "entry": "key2", "col": "val2" }
  303:     ]
  304: 
  305: or a JSON object whose keys are the primary-key values:
  306: 
  307:     {
  308:       "key1": { "col": "val1" },
  309:       "key2": { "col": "val2" }
  310:     }
  311: 
  312: In the object form, each key is injected into its row hash under the C<id>
  313: column name (default C<entry>), so all normal lookups work identically to
  314: the array form.
  315: 
  316: A zero-byte or whitespace-only file is treated as empty - all query methods
  317: return 0 / C<undef> / C<[]> without throwing.
  318: Requires L<JSON::MaybeXS> (loaded lazily).
  319: 
  320: =item 9. C<BerkeleyDB>
  321: 
  322: Binary key-value file ending C<.db>.
  323: 
  324: =item 10. C<HTML>
  325: 
  326: Remote HTML page fetched via a URL.  Pass C<url> instead of C<directory>; the
  327: module fetches the page with L<LWP::UserAgent>, parses all C<< <table> >>
  328: elements with L<HTML::TableExtract>, and slurps the first (or
  329: C<html_table_index>-selected) table into memory.  The first row of the table
  330: is treated as column headers.  Both modules are loaded lazily and are not
  331: required for other backends.
  332: 
  333: =back
  334: 
  335: Pass C<dsn> to bypass file detection entirely and connect via any DBI driver.
  336: Pass C<url> to fetch and slurp a remote HTML table without a local directory.

  469: =head2 new
  470: 
  471: Create an object pointing to a read-only database.
  472: 
  473: Accepts arguments as a hash, a hashref, or - as a shortcut - a single bare
  474: string which is taken to be C<directory>.
  475: 
  476: =head3 Connection parameters
  477: 
  478: =over 4
  479: 
  480: =item * C<directory>
  481: 
  482: Directory containing the data files.  The module probes this directory for
  483: files named after the subclass (see L</FILE FORMATS>).  Required unless
  484: C<dsn> is given.
  485: 
  486: =item * C<dsn>
  487: 
  488: A DBI data-source string (e.g. C<dbi:SQLite:dbname=/path/to/db> or
  489: C<dbi:Pg:dbname=mydb;host=db.example.com>).  When present, file detection
  490: is skipped entirely and the DSN is used directly.  The SQL dialect is
  491: inferred from the DSN prefix (C<sqlite>, C<postgres>, C<mysql>).
  492: 
  493: =item * C<username>
  494: 
  495: Database username.  Used only with C<dsn>; ignored for file-based backends.
  496: 
  497: =item * C<password>
  498: 
  499: Database password.  Used only with C<dsn>; ignored for file-based backends.
  500: 
  501: =item * C<dbname>
  502: 
  503: Override the filename stem searched in C<directory> (default: the table
  504: name derived from the class name).
  505: 
  506: =item * C<table>
  507: 
  508: Override the table (or worksheet) name used in SQL queries for this object.
  509: Default is the class-name-derived table name (e.g. C<Database::Foo> =>
  510: C<foo>).  Particularly useful for Excel workbooks where a single F<.xlsx>
  511: file contains multiple worksheets: pass C<< table => 'Summary' >> to query
  512: the C<Summary> worksheet without creating a dedicated subclass.  Also works
  513: with SQLite/DSN connections to select a table other than the class-derived
  514: default.  The filename stem (C<dbname>) continues to fall back to the class
  515: name, so the correct file is opened regardless of this override.  The value
  516: is validated against C<$SAFE_QUALIFIED> at construction time.
  517: 
  518: =item * C<filename>
  519: 
  520: Override the full filename (relative to C<directory>).  Takes precedence
  521: over C<dbname>.
  522: 
  523: =item * C<host>
  524: 
  525: Remote hostname (or C<user@host>) from which to fetch the data file(s) via
  526: SSH/SCP.  When present, each candidate filename is fetched with
  527: L<File::Slurp::Remote> into a local temporary directory; the existing
  528: extension-based file-type detection then runs against that directory.

 3085: 
 3086: =over 4
 3087: 
 3088: =item *
 3089: 
 3090: B<Read-only.>  No INSERT, UPDATE, or DELETE is provided.  C<execute()>
 3091: runs raw read-only SQL.
 3092: 
 3093: =item *
 3094:

 3096: Pass C<< sep_char => ',' >> for standard RFC 4180 files.
 3097: 
 3098: =item *
 3099: 
 3100: B<Primary-key column is named C<entry>>, not C<key>, because C<key>
 3101: is a SQL reserved word.  Override with the C<id> parameter.
 3102: 
 3103: =item *
 3104: 
 3105: B<XML slurp is limited.>  Only simple flat XML structures are supported
 3106: in slurp mode.  Multi-key or deeply nested documents will croak.
 3107: Force SQL mode with C<< max_slurp_size => 0 >> if slurp fails.
 3108: 
 3109: =item *
 3110: 
 3111: B<Unique key assumption in slurp mode.>  Duplicate values in the key
 3112: column silently overwrite earlier rows.  Disable slurp with
 3113: C<< max_slurp_size => 0 >> if duplicates are expected.
 3114: 
 3115: =item *
 3116: 
 3117: B<BerkeleyDB does not support joins or the chained query builder.>

 3119: =item *
 3120: 
 3121: B<Column names must be valid SQL identifiers> (letters, digits,

 3123: Other characters will cause a croak.
