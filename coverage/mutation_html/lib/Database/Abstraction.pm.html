  109: =head1 DESCRIPTION
  110: 
  111: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
  112: interface over CSV, PSV, TSV, JSON, XML, SQLite, DBM::Deep, BerkeleyDB, and
  113: Excel (XLS/XLSX) files - local, remote (via SSH), or fetched from a URL -
  114: without writing any SQL.
  115: Effectively it allows you to access a database table, of many different
  116: database formats, as an object.
  117: 
  118: Key features:
  119: 
  120: =over 4
  121: 
  122: =item *
  123: 
  124: B<No SQL required.>  Use plain Perl method calls for simple lookups and
  125: scans; switch storage formats without changing application code.
  126: 
  127: =item *
  128: 
  129: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
  130: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
  131: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
  132: C<-between>), and logical groupings (C<-or>, C<-and>).
  133: 
  134: =item *
  135: 
  136: B<Automatic joins.>  Add a C<join> parameter to any select method to
  137: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
  138: 
  139: =item *
  140: 
  141: B<Chained query builder.>  The C<query()> method returns a
  142: L<Database::Abstraction::Query> object for fluent, composable queries:
  143: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  144: 
  145: =item *
  146: 
  147: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  148: returns full type/nullability metadata, using native driver introspection
  149: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  150: 
  151: =item *
  152: 
  153: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  154: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  155: instead of pointing at a local file.
  156: 
  157: =item *
  158: 
  159: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  160: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  161: A CHI-compatible cache layer is also supported.
  162: 
  163: =back
  164:

  269: =head1 FILE FORMATS
  270: 
  271: The module probes the C<directory> for files in this priority order:
  272: 
  273: =over 4
  274: 
  275: =item 1. C<SQLite>
  276: 
  277: File ending C<.sql>, C<.sqlite>, or C<.sqlite3>.
  278: Requires L<DBD::SQLite>.
  279: 
  280: =item 2. C<Deep>
  281: 
  282: DBM::Deep file ending C<.dbm> or C<.deep>.  The entire file is slurped
  283: into a plain Perl hash on open; all in-memory fast-paths apply.
  284: Requires L<DBM::Deep> (loaded lazily).
  285: 
  286: =item 3. C<PSV>
  287: 
  288: Pipe-separated file, ending C<.psv>.
  289: 
  290: =item 4. C<TSV>
  291: 
  292: Tab-separated file, ending C<.tsv>.
  293: 
  294: =item 5. C<CSV>
  295: 
  296: Comma (or custom) separated file, ending C<.csv> or C<.db>; can be
  297: gzipped (C<.csv.gz> or C<.db.gz>).
  298: B<Note:> the default separator is C<!> not C<,> for historical
  299: reasons - pass C<< sep_char => ',' >> for standard CSVs.
  300: Requires L<Text::xSV::Slurp> for the slurp fast-path (loaded lazily).
  301: 
  302: =item 6. C<Excel> (C<.xls>) and C<XLSX> (C<.xlsx>)
  303: 
  304: Two separate Excel backends - one per file format:
  305: 
  306: =over 4
  307: 
  308: =item B<.xls> - old binary format, opened via L<DBD::Excel> (which uses
  309: L<Spreadsheet::ParseExcel> internally).  All queries go through DBI/SQL;
  310: no in-memory slurp path.  C<max_slurp_size> has no effect.
  311: 
  312: =item B<.xlsx> - modern OOXML format, parsed directly via
  313: L<Spreadsheet::ParseXLSX> and slurped into an in-memory hash (keyed mode)
  314: or array (C<no_entry> mode).  No DBI handle is created; all queries use
  315: the in-memory fast-path.  Complex criteria (operator hashes, C<-or>/C<-and>)
  316: will fall through to the SQL path and croak - use simple scalar criteria.
  317: 
  318: =back
  319: 
  320: For both formats, each worksheet is a separate logical table; the active
  321: worksheet is determined by the class-derived table name (or the C<table>
  322: constructor parameter).  Both modules are loaded lazily.
  323: 
  324: =item 7. C<XML>
  325: 
  326: File ending C<.xml>.
  327: Requires L<XML::Simple> for the slurp fast-path (loaded lazily).
  328: 
  329: =item 8. C<JSON>
  330: 
  331: File ending C<.json>, slurped into memory via L<JSON::MaybeXS> (loaded
  332: lazily).
  333: 
  334: The file may contain either a JSON array of row objects:
  335: 
  336:     [
  337:       { "entry": "key1", "col": "val1" },
  338:       { "entry": "key2", "col": "val2" }
  339:     ]
  340: 
  341: or a JSON object whose keys are the primary-key values:
  342: 
  343:     {
  344:       "key1": { "col": "val1" },
  345:       "key2": { "col": "val2" }
  346:     }
  347: 
  348: In the object form, each key is injected into its row hash under the C<id>
  349: column name (default C<entry>), so all normal lookups work identically to
  350: the array form.
  351: 
  352: A zero-byte or whitespace-only file is treated as empty - all query methods
  353: return 0 / C<undef> / C<[]> without throwing.
  354: Requires L<JSON::MaybeXS> (loaded lazily).
  355: 
  356: =item 9. C<BerkeleyDB>
  357: 
  358: Binary key-value file ending C<.db>.
  359: 
  360: =item 10. C<HTML>
  361: 
  362: HTML page fetched via a C<url>.  Pass C<url => 'https://...'> instead of
  363: C<directory>; the module fetches the page with L<LWP::UserAgent::Cached>, parses all
  364: C<< <table> >> elements with L<HTML::TableExtract>, and slurps the first (or
  365: C<html_table_index>-selected) table into memory.  The first row of the table
  366: is treated as column headers.  Both modules are loaded lazily and are not
  367: required for other backends.
  368: 
  369: =back
  370: 
  371: Pass C<dsn> to bypass file detection entirely and connect via any DBI driver.
  372: Pass C<url> to fetch and slurp data from a remote source without a local
  373: directory.  When the URL returns C<Content-Type: application/json> or the URL
  374: path ends in C<.json>, the response is parsed as JSON (see item 8 above).

  522:

  533: files named after the subclass (see L</FILE FORMATS>).  Required unless
