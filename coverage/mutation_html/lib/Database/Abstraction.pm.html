   73: =head1 DESCRIPTION
   74: 
   75: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
   76: interface over CSV, PSV, XML, SQLite, DBM::Deep, and BerkeleyDB files - without writing
   77: any SQL.
   78: 
   79: Key features:
   80: 
   81: =over 4
   82: 
   83: =item *
   84: 
   85: B<No SQL required.>  Use plain Perl method calls for simple lookups and
   86: scans; switch storage formats without changing application code.
   87: 
   88: =item *
   89: 
   90: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
   91: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
   92: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
   93: C<-between>), and logical groupings (C<-or>, C<-and>).
   94: 
   95: =item *
   96: 
   97: B<Automatic joins.>  Add a C<join> parameter to any select method to
   98: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
   99: 
  100: =item *
  101: 
  102: B<Chained query builder.>  The C<query()> method returns a
  103: L<Database::Abstraction::Query> object for fluent, composable queries:
  104: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  105: 
  106: =item *
  107: 
  108: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  109: returns full type/nullability metadata, using native driver introspection
  110: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  111: 
  112: =item *
  113: 
  114: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  115: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  116: instead of pointing at a local file.
  117: 
  118: =item *
  119: 
  120: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  121: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  122: A CHI-compatible cache layer is also supported.
  123: 
  124: =back

  397: =head2 new
  398: 
  399: Create an object pointing to a read-only database.
  400: 
  401: Accepts arguments as a hash, a hashref, or - as a shortcut - a single bare

  404: =head3 Connection parameters
  405: 
  406: =over 4
  407: 
  408: =item * C<directory>
  409: 
  410: Directory containing the data files.  The module probes this directory for
  411: files named after the subclass (see L</FILE FORMATS>).  Required unless
  412: C<dsn> is given.
  413: 
  414: =item * C<dsn>
  415: 
  416: A DBI data-source string (e.g. C<dbi:SQLite:dbname=/path/to/db> or
  417: C<dbi:Pg:dbname=mydb;host=db.example.com>).  When present, file detection
  418: is skipped entirely and the DSN is used directly.  The SQL dialect is
  419: inferred from the DSN prefix (C<sqlite>, C<postgres>, C<mysql>).
  420: 
  421: =item * C<username>
  422: 
  423: Database username.  Used only with C<dsn>; ignored for file-based backends.
  424: 
  425: =item * C<password>
  426: 
  427: Database password.  Used only with C<dsn>; ignored for file-based backends.
  428: 
  429: =item * C<dbname>
  430: 
  431: Override the filename stem searched in C<directory> (default: the table
  432: name derived from the class name).
  433: 
  434: =item * C<filename>
  435: 
  436: Override the full filename (relative to C<directory>).  Takes precedence
  437: over C<dbname>.
  438: 
  439: =item * C<host>
  440: 
  441: Remote hostname (or C<user@host>) from which to fetch the data file(s) via
  442: SSH/SCP.  When present, each candidate filename is fetched with
  443: L<File::Slurp::Remote> into a local temporary directory; the existing
  444: extension-based file-type detection then runs against that directory.
  445: C<directory> is treated as the remote path (no local canonicalization is
  446: applied).  Using C<filename> together with C<host> avoids probing multiple
  447: extensions and is therefore more efficient.  L<File::Slurp::Remote> must be
  448: installed; it is loaded lazily (only when C<host> is given).
