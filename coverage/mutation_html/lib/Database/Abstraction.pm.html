  111: =head1 DESCRIPTION
  112: 
  113: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
  114: interface over CSV, PSV, TSV, JSON, XML, SQLite, DBM::Deep, BerkeleyDB, and
  115: Excel (XLS/XLSX) files - local, remote (via SSH), or fetched from a URL -
  116: without writing any SQL.
  117: Effectively it allows you to access a database table, of many different
  118: database formats, as an object.
  119: 
  120: Key features:
  121: 
  122: =over 4
  123: 
  124: =item *
  125: 
  126: B<No SQL required.>  Use plain Perl method calls for simple lookups and
  127: scans; switch storage formats without changing application code.
  128: 
  129: =item *
  130: 
  131: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
  132: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
  133: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
  134: C<-between>), and logical groupings (C<-or>, C<-and>).
  135: 
  136: =item *
  137: 
  138: B<Automatic joins.>  Add a C<join> parameter to any select method to
  139: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
  140: 
  141: =item *
  142: 
  143: B<Chained query builder.>  The C<query()> method returns a
  144: L<Database::Abstraction::Query> object for fluent, composable queries:
  145: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  146: 
  147: =item *
  148: 
  149: B<Aggregation.>  The C<aggregate()> method and the fluent
  150: C<< ->group_by()->measure()->having()->all() >> chain push C<GROUP BY> to
  151: SQL backends and fold rows in Perl on slurp-only backends.
  152: 
  153: =item *
  154: 
  155: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  156: returns full type/nullability metadata, using native driver introspection
  157: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  158: 
  159: =item *
  160: 
  161: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  162: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  163: instead of pointing at a local file.
  164: 
  165: =item *
  166: 
  167: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  168: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  169: A CHI-compatible cache layer is also supported.
  170: 
  171: =back

  277: =head1 FILE FORMATS
  278: 
  279: The module probes the C<directory> for files in this priority order:
  280: 
  281: =over 4
  282: 
  283: =item 1. C<SQLite>
  284: 
  285: File ending C<.sql>, C<.sqlite>, or C<.sqlite3>.
  286: Requires L<DBD::SQLite>.
  287: 
  288: =item 2. C<Deep>
  289: 
  290: DBM::Deep file ending C<.dbm> or C<.deep>.  The entire file is slurped
  291: into a plain Perl hash on open; all in-memory fast-paths apply.
  292: Requires L<DBM::Deep> (loaded lazily).
  293: 
  294: =item 3. C<PSV>
  295: 
  296: Pipe-separated file, ending C<.psv>.
  297: 
  298: =item 4. C<TSV>
  299: 
  300: Tab-separated file, ending C<.tsv>.
  301: 
  302: =item 5. C<CSV>
  303: 
  304: Comma (or custom) separated file, ending C<.csv> or C<.db>; can be
  305: gzipped (C<.csv.gz> or C<.db.gz>).
  306: B<Note:> the default separator is C<!> not C<,> for historical
  307: reasons - pass C<< sep_char => ',' >> for standard CSVs.
  308: Requires L<Text::xSV::Slurp> for the slurp fast-path (loaded lazily).
  309: 
  310: =item 6. C<Excel> (C<.xls>) and C<XLSX> (C<.xlsx>)
  311: 
  312: Two separate Excel backends - one per file format:
  313: 
  314: =over 4
  315: 
  316: =item B<.xls> - old binary format, opened via L<DBD::Excel> (which uses
  317: L<Spreadsheet::ParseExcel> internally).  All queries go through DBI/SQL;
  318: no in-memory slurp path.  C<max_slurp_size> has no effect.
  319: 
  320: =item B<.xlsx> - modern OOXML format, parsed directly via
  321: L<Spreadsheet::ParseXLSX> and slurped into an in-memory hash (keyed mode)
  322: or array (C<no_entry> mode).  No DBI handle is created; all queries use
  323: the in-memory fast-path.  Complex criteria (operator hashes, C<-or>/C<-and>)
  324: will fall through to the SQL path and croak - use simple scalar criteria.
  325: 
  326: =back
  327: 
  328: For both formats, each worksheet is a separate logical table; the active
  329: worksheet is determined by the class-derived table name (or the C<table>
  330: constructor parameter).  Both modules are loaded lazily.
  331: 
  332: =item 7. C<XML>
  333: 
  334: File ending C<.xml>.
  335: Requires L<XML::Simple> for the slurp fast-path (loaded lazily).
  336: 
  337: =item 8. C<JSON>
  338: 
  339: File ending C<.json>, slurped into memory via L<JSON::MaybeXS> (loaded
  340: lazily).
  341: 
  342: The file may contain either a JSON array of row objects:
  343: 
  344:     [
  345:       { "entry": "key1", "col": "val1" },
  346:       { "entry": "key2", "col": "val2" }
  347:     ]
  348: 
  349: or a JSON object whose keys are the primary-key values:
  350: 
  351:     {
  352:       "key1": { "col": "val1" },
  353:       "key2": { "col": "val2" }
  354:     }
  355: 
  356: In the object form, each key is injected into its row hash under the C<id>
  357: column name (default C<entry>), so all normal lookups work identically to
  358: the array form.
  359: 
  360: A zero-byte or whitespace-only file is treated as empty - all query methods
  361: return 0 / C<undef> / C<[]> without throwing.
  362: Requires L<JSON::MaybeXS> (loaded lazily).
  363: 
  364: =item 9. C<BerkeleyDB>
  365: 
  366: Binary key-value file ending C<.db>.
  367: 
  368: =item 10. C<HTML>
  369: 
  370: HTML page fetched via a C<url>.  Pass C<url => 'https://...'> instead of
  371: C<directory>; the module fetches the page with L<LWP::UserAgent::Cached>, parses all
  372: C<< <table> >> elements with L<HTML::TableExtract>, and slurps the first (or
  373: C<html_table_index>-selected) table into memory.  The first row of the table
  374: is treated as column headers.  Both modules are loaded lazily and are not
  375: required for other backends.
  376: 
  377: =back
  378: 
  379: Pass C<dsn> to bypass file detection entirely and connect via any DBI driver.
  380: Pass C<url> to fetch and slurp data from a remote source without a local
  381: directory.  When the URL returns C<Content-Type: application/json> or the URL
  382: path ends in C<.json>, the response is parsed as JSON (see item 8 above).
  383: Otherwise the response is parsed as an HTML page (item 10).

 4734: =item C<< I<Class>: aggregate: duplicate measure alias 'I<as>' >>
 4735: 
 4736: Two measure hashrefs share the same C<as> alias.
 4737: 
 4738: =item C<< I<Class>: aggregate: measure alias 'I<as>' collides with a group-by column >>
 4739: 
 4740: A measure alias duplicates a name in the C<by> list.
 4741: 
 4742: =item C<< I<Class>: aggregate: 'by' must be an arrayref of column names >>
 4743: 
 4744: The C<by> parameter was not an arrayref.
 4745: 
 4746: =item C<< I<Class>: aggregate: unsafe group-by column 'I<col>' >>
 4747: 
 4748: A C<by> element is not a valid SQL identifier.
 4749: 
 4750: =item C<< I<Class>: aggregate: having key 'I<key>' is not a group-by column or measure alias >>
 4751: 
 4752: A C<having> key does not match any C<by> column name or measure C<as> alias.
 4753: 
 4754: =item C<< I<Class>: aggregate: sort_by names 'I<name>', which is not a group-by column or measure alias >>
 4755: 
 4756: The C<sort_by> column is not one of the C<by> columns or measure aliases.
 4757: 
 4758: =item C<< I<Class>: aggregate: cannot aggregate a JOIN on the I<backend> backend >>
 4759: 
 4760: C<join> was passed to C<aggregate()> on a slurp-only backend that has no DBI handle.
 4761: 
 4762: =item C<< Database::Abstraction::Query: count() is not available once measure() has been called >>
 4763: 
 4764: C<count()> was called on a query builder that has measures set.  Use C<all()> and check C<scalar @{$rows}>.

 4768: =head1 KNOWN LIMITATIONS
 4769: 
 4770: =over 4
 4771: 
 4772: =item *
 4773: 
 4774: B<Read-only.>  No INSERT, UPDATE, or DELETE is provided.  C<execute()>
 4775: runs raw read-only SQL.
 4776: 
 4777: =item *
 4778: 
 4779: B<Default CSV separator is C<!>>, not C<,>, for historical reasons.
 4780: Pass C<< sep_char => ',' >> for standard RFC 4180 files.
 4781: 
 4782: =item *
 4783: 
 4784: B<Primary-key column is named C<entry>>, not C<key>, because C<key>
 4785: is a SQL reserved word.  Override with the C<id> parameter.
 4786: 
 4787: =item *
 4788: 
 4789: B<XML slurp is limited.>  Only simple flat XML structures are supported
 4790: in slurp mode.  Multi-key or deeply nested documents will croak.
 4791: Force SQL mode with C<< max_slurp_size => 0 >> if slurp fails.
 4792: 
 4793: =item *
 4794: 
 4795: B<Unique key assumption in slurp mode.>  Duplicate values in the key
 4796: column silently overwrite earlier rows.  Disable slurp with
 4797: C<< max_slurp_size => 0 >> if duplicates are expected.
 4798: 
 4799: =item *
 4800: 
 4801: B<BerkeleyDB does not support joins or the chained query builder.>
 4802: 
 4803: =item *
 4804: 
 4805: B<Column names must be valid SQL identifiers> (letters, digits,
 4806: underscores, and a single dot for C<table.column> join notation).
 4807: Other characters will cause a croak.
 4808: 
 4809: =item *
 4810: 
 4811: B<count() cache is opportunistic.>  Count results are served from cache
 4812: only when a prior C<selectall_arrayref()> or C<count()> call with the
 4813: same criteria has already populated it.
