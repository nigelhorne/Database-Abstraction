   73: =head1 DESCRIPTION
   74: 
   75: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
   76: interface over CSV, PSV, XML, SQLite, DBM::Deep, BerkeleyDB, and Excel (XLSX)
   77: files - local, remote (via SSH), or fetched from a URL - without writing any
   78: SQL.
   79: Effectively it allows you to access a database table, of many different
   80: database formats, as an object.
   81: 
   82: Key features:
   83: 
   84: =over 4
   85: 
   86: =item *
   87: 
   88: B<No SQL required.>  Use plain Perl method calls for simple lookups and
   89: scans; switch storage formats without changing application code.
   90: 
   91: =item *
   92: 
   93: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
   94: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
   95: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
   96: C<-between>), and logical groupings (C<-or>, C<-and>).
   97: 
   98: =item *
   99: 
  100: B<Automatic joins.>  Add a C<join> parameter to any select method to
  101: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
  102: 
  103: =item *
  104: 
  105: B<Chained query builder.>  The C<query()> method returns a
  106: L<Database::Abstraction::Query> object for fluent, composable queries:
  107: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  108: 
  109: =item *
  110: 
  111: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  112: returns full type/nullability metadata, using native driver introspection
  113: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  114: 
  115: =item *
  116: 
  117: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  118: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  119: instead of pointing at a local file.
  120: 
  121: =item *
  122: 
  123: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  124: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  125: A CHI-compatible cache layer is also supported.
  126: 
  127: =back

  256:

  264: =item 5. C<Excel> (C<.xls>) and C<XLSX> (C<.xlsx>)
  265: 
  266: Two separate Excel backends - one per file format:
  267: 
  268: =over 4
  269: 
  270: =item B<.xls> - old binary format, opened via L<DBD::Excel> (which uses
  271: L<Spreadsheet::ParseExcel> internally).  All queries go through DBI/SQL;
  272: no in-memory slurp path.  C<max_slurp_size> has no effect.
  273: 
  274: =item B<.xlsx> - modern OOXML format, parsed directly via
  275: L<Spreadsheet::ParseXLSX> and slurped into an in-memory hash (keyed mode)
  276: or array (C<no_entry> mode).  No DBI handle is created; all queries use
  277: the in-memory fast-path.  Complex criteria (operator hashes, C<-or>/C<-and>)
  278: will fall through to the SQL path and croak - use simple scalar criteria.
  279: 
  280: =back
  281: 
  282: For both formats, each worksheet is a separate logical table; the active
  283: worksheet is determined by the class-derived table name (or the C<table>
  284: constructor parameter).  Both modules are loaded lazily.
  285: 
  286: =item 6. C<XML>
  287: 
  288: File ending C<.xml>
  289: 
  290: =item 7. C<BerkeleyDB>
  291: 
  292: Binary key-value file ending C<.db>
  293: 
  294: =item 8. C<HTML>
  295:

  302: 
  303: =back

  305: Pass C<dsn> to bypass file detection entirely and connect via any DBI driver.

  439: =head2 new
  440: 
  441: Create an object pointing to a read-only database.
  442: 
  443: Accepts arguments as a hash, a hashref, or - as a shortcut - a single bare
  444: string which is taken to be C<directory>.
  445: 
  446: =head3 Connection parameters
  447: 
  448: =over 4
  449: 
  450: =item * C<directory>
  451: 
  452: Directory containing the data files.  The module probes this directory for
  453: files named after the subclass (see L</FILE FORMATS>).  Required unless
  454: C<dsn> is given.
  455: 
  456: =item * C<dsn>
  457: 
  458: A DBI data-source string (e.g. C<dbi:SQLite:dbname=/path/to/db> or
  459: C<dbi:Pg:dbname=mydb;host=db.example.com>).  When present, file detection
  460: is skipped entirely and the DSN is used directly.  The SQL dialect is
  461: inferred from the DSN prefix (C<sqlite>, C<postgres>, C<mysql>).
  462: 
  463: =item * C<username>
  464: 
  465: Database username.  Used only with C<dsn>; ignored for file-based backends.
  466: 
  467: =item * C<password>
  468: 
  469: Database password.  Used only with C<dsn>; ignored for file-based backends.
  470: 
  471: =item * C<dbname>
  472: 
  473: Override the filename stem searched in C<directory> (default: the table
  474: name derived from the class name).
  475: 
  476: =item * C<table>
  477: 
  478: Override the table (or worksheet) name used in SQL queries for this object.
  479: Default is the class-name-derived table name (e.g. C<Database::Foo> =>
  480: C<foo>).  Particularly useful for Excel workbooks where a single F<.xlsx>
  481: file contains multiple worksheets: pass C<< table => 'Summary' >> to query
  482: the C<Summary> worksheet without creating a dedicated subclass.  Also works
  483: with SQLite/DSN connections to select a table other than the class-derived
  484: default.  The filename stem (C<dbname>) continues to fall back to the class
  485: name, so the correct file is opened regardless of this override.  The value
  486: is validated against C<$SAFE_QUALIFIED> at construction time.
  487: 
  488: =item * C<filename>
  489: 
  490: Override the full filename (relative to C<directory>).  Takes precedence
  491: over C<dbname>.
  492: 
  493: =item * C<host>
  494: 
  495: Remote hostname (or C<user@host>) from which to fetch the data file(s) via
  496: SSH/SCP.  When present, each candidate filename is fetched with
  497: L<File::Slurp::Remote> into a local temporary directory; the existing
  498: extension-based file-type detection then runs against that directory.
  499: C<directory> is treated as the remote path (no local canonicalization is
  500: applied).  Using C<filename> together with C<host> avoids probing multiple
  501: extensions and is therefore more efficient.  L<File::Slurp::Remote> must be
  502: installed; it is loaded lazily (only when C<host> is given).
  503: 
  504: =item * C<url>
  505: 
  506: A URL (C<http://> or C<https://>) pointing to an HTML page that contains one
  507: or more C<< <table> >> elements.  When present, C<directory> is not required.
  508: The first row of the selected table is used as column headers.
  509: Requires L<LWP::UserAgent> and L<HTML::TableExtract> (both loaded lazily).
  510: 
  511: =back
