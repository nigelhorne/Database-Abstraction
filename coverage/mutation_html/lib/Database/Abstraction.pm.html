   70: =head1 DESCRIPTION
   71: 
   72: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
   73: interface over CSV, PSV, XML, SQLite, DBM::Deep, and BerkeleyDB files - without writing
   74: any SQL.
   75: 
   76: Key features:
   77: 
   78: =over 4
   79: 
   80: =item *
   81: 
   82: B<No SQL required.>  Use plain Perl method calls for simple lookups and
   83: scans; switch storage formats without changing application code.
   84: 
   85: =item *
   86: 
   87: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
   88: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
   89: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
   90: C<-between>), and logical groupings (C<-or>, C<-and>).
   91: 
   92: =item *
   93: 
   94: B<Automatic joins.>  Add a C<join> parameter to any select method to
   95: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
   96: 
   97: =item *
   98: 
   99: B<Chained query builder.>  The C<query()> method returns a
  100: L<Database::Abstraction::Query> object for fluent, composable queries:
  101: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  102: 
  103: =item *
  104: 
  105: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  106: returns full type/nullability metadata, using native driver introspection
  107: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  108: 
  109: =item *
  110: 
  111: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  112: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  113: instead of pointing at a local file.
  114: 
  115: =item *
  116: 
  117: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  118: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  119: A CHI-compatible cache layer is also supported.
  120: 
  121: =back

  394: =head2 new
  395: 
  396: Create an object pointing to a read-only database.
  397: 
  398: Accepts arguments as a hash, a hashref, or - as a shortcut - a single bare
  399: string which is taken to be C<directory>.

  401: =head3 Connection parameters
  402: 
  403: =over 4
  404: 
  405: =item * C<directory>
  406: 
  407: Directory containing the data files.  The module probes this directory for
  408: files named after the subclass (see L</FILE FORMATS>).  Required unless
  409: C<dsn> is given.
  410: 
  411: =item * C<dsn>
  412: 
  413: A DBI data-source string (e.g. C<dbi:SQLite:dbname=/path/to/db> or
  414: C<dbi:Pg:dbname=mydb;host=db.example.com>).  When present, file detection
  415: is skipped entirely and the DSN is used directly.  The SQL dialect is
  416: inferred from the DSN prefix (C<sqlite>, C<postgres>, C<mysql>).
  417: 
  418: =item * C<username>
  419: 
  420: Database username.  Used only with C<dsn>; ignored for file-based backends.
  421: 
  422: =item * C<password>
  423: 
  424: Database password.  Used only with C<dsn>; ignored for file-based backends.
  425: 
  426: =item * C<dbname>
  427: 
  428: Override the filename stem searched in C<directory> (default: the table
  429: name derived from the class name).
  430: 
  431: =item * C<filename>
  432: 
  433: Override the full filename (relative to C<directory>).  Takes precedence
  434: over C<dbname>.
  435: 
  436: =item * C<host>
  437: 
  438: Remote hostname (or C<user@host>) from which to fetch the data file(s) via
  439: SSH/SCP.  When present, each candidate filename is fetched with
  440: L<File::Slurp::Remote> into a local temporary directory; the existing
  441: extension-based file-type detection then runs against that directory.
  442: C<directory> is treated as the remote path (no local canonicalization is
  443: applied).  Using C<filename> together with C<host> avoids probing multiple
  444: extensions and is therefore more efficient.  L<File::Slurp::Remote> must be
  445: installed; it is loaded lazily (only when C<host> is given).

  449: =head3 Behaviour parameters
  450: 
  451: =over 4
  452: 
  453: =item * C<no_entry>
  454:

 2757: 
 2758: =over 4
 2759: 
 2760: =item *
 2761: 
 2762: B<Read-only.>  No INSERT, UPDATE, or DELETE is provided.  C<execute()>
 2763: runs raw read-only SQL.
 2764: 
 2765: =item *
 2766: 
 2767: B<Default CSV separator is C<!>>, not C<,>, for historical reasons.

 2770: =item *
 2771: 
 2772: B<Primary-key column is named C<entry>>, not C<key>, because C<key>

 2774: 
 2775: =item *
 2776: 
 2777: B<XML slurp is limited.>  Only simple flat XML structures are supported
 2778: in slurp mode.  Multi-key or deeply nested documents will croak.
 2779: Force SQL mode with C<< max_slurp_size => 0 >> if slurp fails.
 2780: 
 2781: =item *
 2782: 
 2783: B<Unique key assumption in slurp mode.>  Duplicate values in the key
 2784: column silently overwrite earlier rows.  Disable slurp with
 2785: C<< max_slurp_size => 0 >> if duplicates are expected.
 2786: 
 2787: =item *
 2788: 
 2789: B<BerkeleyDB does not support joins or the chained query builder.>
 2790: 
 2791: =item *
 2792: 
 2793: B<Column names must be valid SQL identifiers> (letters, digits,
 2794: underscores, and a single dot for C<table.column> join notation).
 2795: Other characters will cause a croak.
 2796: 
 2797: =item *
 2798: 
 2799: B<count() cache is opportunistic.>  Count results are served from cache
