   74: =head1 DESCRIPTION
   75: 
   76: C<Database::Abstraction> is a read-only ORM for Perl that gives a uniform
   77: interface over CSV, PSV, TSV, JSON, XML, SQLite, DBM::Deep, BerkeleyDB, and
   78: Excel (XLS/XLSX) files - local, remote (via SSH), or fetched from a URL -
   79: without writing any SQL.
   80: Effectively it allows you to access a database table, of many different
   81: database formats, as an object.
   82: 
   83: Key features:
   84: 
   85: =over 4
   86: 
   87: =item *
   88: 
   89: B<No SQL required.>  Use plain Perl method calls for simple lookups and
   90: scans; switch storage formats without changing application code.
   91: 
   92: =item *
   93: 
   94: B<Rich query criteria.>  Pass plain values, SQL wildcards, C<undef> (IS NULL),
   95: comparison operators (C<< > >> C<< < >> C<< >= >> C<< <= >> C<!=>), pattern
   96: operators (C<-like>, C<-not_like>), set operators (C<-in>, C<-not_in>,
   97: C<-between>), and logical groupings (C<-or>, C<-and>).
   98: 
   99: =item *
  100: 
  101: B<Automatic joins.>  Add a C<join> parameter to any select method to
  102: combine tables with INNER, LEFT, RIGHT, FULL, or CROSS joins.
  103: 
  104: =item *
  105: 
  106: B<Chained query builder.>  The C<query()> method returns a
  107: L<Database::Abstraction::Query> object for fluent, composable queries:
  108: C<< $db->query->where(...)->order_by(...)->limit(...)->all() >>.
  109: 
  110: =item *
  111: 
  112: B<Schema introspection.>  C<columns()> lists column names; C<schema()>
  113: returns full type/nullability metadata, using native driver introspection
  114: (C<PRAGMA table_info> for SQLite, C<column_info> for others).
  115: 
  116: =item *
  117: 
  118: B<DSN portability.>  Pass a C<dsn> (plus optional C<username>/C<password>)
  119: to connect to any DBI-supported database (SQLite, PostgreSQL, MySQL, ...)
  120: instead of pointing at a local file.
  121: 
  122: =item *
  123: 
  124: B<Performance.>  Small files are slurped into a RAM hash for sub-millisecond
  125: lookups.  All DBI statement handles are cached with C<prepare_cached()>.
  126: A CHI-compatible cache layer is also supported.
  127: 
  128: =back

  266: 
  267: =item 6. C<Excel> (C<.xls>) and C<XLSX> (C<.xlsx>)
  268: 
  269: Two separate Excel backends - one per file format:
  270: 
  271: =over 4
  272: 
  273: =item B<.xls> - old binary format, opened via L<DBD::Excel> (which uses
  274: L<Spreadsheet::ParseExcel> internally).  All queries go through DBI/SQL;
  275: no in-memory slurp path.  C<max_slurp_size> has no effect.
  276:

  279: or array (C<no_entry> mode).  No DBI handle is created; all queries use
  280: the in-memory fast-path.  Complex criteria (operator hashes, C<-or>/C<-and>)
  281: will fall through to the SQL path and croak - use simple scalar criteria.
  282: 
  283: =back

  285: For both formats, each worksheet is a separate logical table; the active
  286: worksheet is determined by the class-derived table name (or the C<table>
  287: constructor parameter).  Both modules are loaded lazily.
  288: 
  289: =item 7. C<XML>
  290: 
  291: File ending C<.xml>.
  292: Requires L<XML::Simple> for the slurp fast-path (loaded lazily).
  293: 
  294: =item 8. C<JSON>
  295: 
  296: File ending C<.json>, slurped into memory via L<JSON::MaybeXS> (loaded
  297: lazily).
  298: 
  299: The file may contain either a JSON array of row objects:
  300: 
  301:     [
  302:       { "entry": "key1", "col": "val1" },
  303:       { "entry": "key2", "col": "val2" }
  304:     ]
  305: 
  306: or a JSON object whose keys are the primary-key values:

  308:     {

  319: Requires L<JSON::MaybeXS> (loaded lazily).
  320: 
  321: =item 9. C<BerkeleyDB>
  322: 
  323: Binary key-value file ending C<.db>.
  324: 
  325: =item 10. C<HTML>
  326:

  485: 
  486: Create an object pointing to a read-only database.
  487: 
  488: Accepts arguments as a hash, a hashref, or - as a shortcut - a single bare

  501: =item * C<dsn>
  502:

  508: =item * C<username>

  510: Database username.  Used only with C<dsn>; ignored for file-based backends.
