   70: =head1 DESCRIPTION
   71: 
   72: C<Database::Abstraction::Query> is a fluent query builder returned by
   73: C<< $db->query() >>.  You assemble a query by chaining builder methods,
   74: then execute it with a terminal method.
   75: 
   76: =over 4
   77: 
   78: =item *
   79: 
   80: B<Builder methods> (C<select>, C<where>, C<join>, C<order_by>, C<limit>,
   81: C<offset>, C<group_by>, C<measure>, C<having>) all return C<$self>, so
   82: calls can be chained in any order.
   83: 
   84: =item *
   85: 
   86: B<Terminal methods> (C<all>, C<first>, C<count>) assemble the SQL, execute
   87: it, and return the result.  Each terminal method can be called on the same
   88: builder object independently - calling C<first()> does not modify the stored
   89: state (it temporarily sets LIMIT 1 internally).
   90: 
   91: =item *
   92: 
   93: C<where()> calls are B<merged with AND semantics>: each call adds more
   94: required conditions.  To express OR conditions pass C<< -or => [...] >> as a
   95: key inside a single C<where()> call.
   96: 
   97: =item *
   98: 
   99: The C<join> parameter accepts the same spec as the C<join> parameter in
  100: L<Database::Abstraction/QUERY CRITERIA>.
  101: 
  102: =item *
  103: 
  104: BerkeleyDB backends support C<all()>, C<first()>, and C<count()> with
  105: C<where()> criteria and C<order_by()>/C<limit()>/C<offset()> applied in Perl.
  106: The C<join()> builder method and the C<select()> column projection are not
  107: supported on BerkeleyDB and will raise an error.
  108: 
  109: =back
